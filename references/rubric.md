# AI 协作成熟度评估 · 评分细则

## 段位表（AI 范式阶梯）

子段位：base → Pro → Max（模型命名梗）。

| 段位 | 分数 | 一句话 | 附加条件 |
|---|---|---|---|
| 冷启动 ❄️ | — | 训练数据不足，暂不定级 | 真人会话 <15 |
| 聊天框玩家 / Pro / Max | 0-19 / 20-29 / 30-39 | 还在和 AI 一问一答 | |
| 提示词工程师 / Pro / Max | 40-46 / 47-53 / 54-59 | 会说话了，还没放权 | |
| 工具调用者 / Pro / Max | 60-64 / 65-69 / 70-74 | Function Calling 已觉醒 | |
| 智能体指挥 / Pro / Max | 75-79 / 80-84 / 85-89 | Agentic 时代玩家 | |
| 多智能体编排者 | ≥90 | 同时指挥一个 AI 车间 | 硬成就 ≥2/3，否则封顶智能体指挥 Max |
| 人机合一 | ≥95 | 稀有段位 · 顶点 | 硬成就 3/3 |

**三枚硬成就**（从 stats.json 实证）：
- ⚙️ 无人值守：`automation_sessions > 0` 且分布在多个日期
- ⚡ 多线程人生：`par_ratio ≥ 0.2` 或有子代理使用记录
- 📦 万物皆可 skill：重复 ≥3 次请求组的固化率 ≥60%（对照实存）

参照系（报告顶部原话照抄）："本评分体系刻意从严——聊天框/提示词段为新手常态 · 工具调用者已是熟练 · 智能体指挥为重度用户 · 多智能体编排者以上需硬成就，人机合一为稀有段位。"

## 行业覆盖层

行业不只换场景清单——**直接改写评分子项**。判读时先套用所选行业的覆盖规则，未覆盖的子项按通用细则。

### 核心分野（判读前先建立这个框架）

| | 证券金融 | 法律 |
|---|---|---|
| 最怕什么 | **数字错**（幻觉数字进报告=事故） | **引用假**（假法条假案例=执业风险） |
| "弹药"因此意味着 | 权威数据源接入 | 法律检索通道接入 |
| "验收"因此意味着 | 数字溯源（as-of 日期、口径）、双源核对 | 每条法条/案例引用要出处、要核验 |
| 沉淀的主形态 | 自动化监控（公告/舆情/定期报表） | 模板化文书（合同、函件、意见书模板） |

### 证券金融覆盖规则

场景基准：研报与纪要 / 数据处理（财报提取、行情查询、双源核对、估值）/ 文档产出（客户材料、PPT、披露初稿、监管报送）/ 监控自动化 / 事务支持。

**替换「三、上下文供给」子项：**
得分项：接入权威行情/财务数据源（Wind、同花顺 iFinD、东方财富 Choice、akshare 任一，MCP/skill 形态）＝5；企业信息与公告通道（企查查/天眼查/巨潮资讯）＝3；喂研报/财报原文而非口述数字＝4；工具与场景匹配＝3
扣分项：让模型徒手回答行情、财务数字、估值倍数而不接数据源：−4；同类数据源装 3 个以上：−2

**替换「四、验收与纠偏」子项：**
得分项：实质检查＝5；诊断式纠偏占比（≥60%→6 / 30-60%→3 / 更低→1）；要求数字带 as-of 与口径、或做双源核对＝4
扣分项：复读式重试≥3 次：−3；采用了无溯源数字且未追问出处：−2

**行业红线（总分层面扣，−3/次，至多 −6）：**客户身份信息、账户信息、未公开项目/交易信息明文贴入对话。

**工具基准表（"该装没装"按此评）：**
- 机构级：Wind / 同花顺 iFinD / 东方财富 Choice 任一（机构事实标准，有内网权限就该接）＋企查查或天眼查
- 免费够用档：akshare（行情财务）＋巨潮资讯（公告）＋雪球（实时）
- 文档侧：官方 pptx / docx / xlsx ＋ 财务建模类（DCF、可比公司）skill
- 缺失判定：日常有数据类任务但一个数据通道都没接——上下文维度按最低档处理

### 法律覆盖规则

场景基准：合同与文书 / 法条案例检索 / 尽调与诉讼 / 事务支持 / 法规监控自动化。

**替换「三、上下文供给」子项：**
得分项：接入法律检索通道（北大法宝、威科先行、华宇元典等数据库，MCP/connector 形态）＝6；喂合同/卷宗原文而非转述＝4；有模板库/条款库沉淀可引用＝2；工具与场景匹配＝3
扣分项：让模型凭记忆背法条/案例并直接采用：−5（比金融的徒手数字扣得更重——引用幻觉是执业风险）

**替换「四、验收与纠偏」子项：**
得分项：实质检查＝5；诊断式纠偏＝4；对每条法条/案例引用要求给出处并核验＝4；要求区分"法律意见"与"信息整理"的边界＝2
扣分项：直接采用未核验引用且未追问出处：−3；复读式重试≥3 次：−2

**行业红线（−3/次，至多 −6）：**当事人可识别信息、受特权保护信息明文贴入对话。

**工具基准表：**
- 专业级：北大法宝 / 威科先行 / 华宇元典 任一 ＋ 企查查（尽调用）
- 够用档：官方 docx ＋ 合同比对/审查类 skill ＋ 公开裁判文书检索
- 缺失判定：做检索类任务却零检索通道、纯靠模型记忆——上下文维度按最低档处理

### 通用（无行业假设）

场景基准：文档 / 表格 / 网页操作 / 数据查询 / 定时任务 / 本机文件 / 咨询问答。评分全按六维通用细则，无覆盖。

## 六维评分（总分 100）

权重按影响链：交代错→全错（20）；不放权→上限低（20）；其余各 15。
纪律：先证据后给分；每维至少引两条真实会话；证据不足就近取低；维度内先加得分项再减扣分项，下限 0。
**白话纪律**：dims[].comment 必须是普通同事一听就懂的大白话（禁止出现"目标级委托""诊断式纠偏"等术语，术语只能出现在 detail 里）；summary_plain 同理。写完自查：把 comment 念给一个不懂 AI 的人听，听不懂就重写。

### 一、任务交代（20）
得分项：首条要素完备（目标2/材料2/验收标准3/格式1）＝8；一次说清率（只统计 ≤5 轮的单任务会话中 1-2 轮收工占比：≥60%→8 / 40-60%→5 / 20-40%→3 / 更低→1）；参考范例习惯＝4
扣分项：许愿式开场（复杂任务首条一句话且无材料）占比>40%：−4；后续轮次一半以上在补第一轮该说的：−3

### 二、授权与编排（20）
得分项：目标级委托占比（≥60%→8 / 40-60%→5 / 更低→2）；并行开工（常有＝6 / 偶尔＝3 / 从无＝0，看 par_ratio 与子代理）；任务颗粒适中（不微操不甩巨型任务）＝6
扣分项：步进式指挥>50%：−5；巨型任务一句话甩且失败率高：−3

### 三、上下文供给（15）
得分项：复杂任务主动喂文件/接数据源/给链接占比（≥50%→8 / 25-50%→5 / 更低→2）；工具配置与行业场景匹配＝4；让 agent 自己读文件而非手工粘贴＝3
扣分项：干聊复杂事实任务后抱怨不准：−3；同类工具装 3 个以上：−2

### 四、验收与纠偏（15）
得分项：对复杂产出有实质检查＝7；诊断式纠偏占负反馈比例（≥60%→6 / 30-60%→3 / 更低→1）；要求复核关键数字来源＝2
扣分项：复读式重试≥3 次：−3；长产出零验收隔天返工：−2

### 五、资产沉淀（15）
得分项：重复≥3 次请求固化率（≥60%→8 / 30-60%→5 / 更低→2，以实存为证）；定时任务/自动化真实运行＝4；模板/记忆/规则沉淀＝3
扣分项：金鱼记忆（同一事≥5 次每次从头交代）每组 −2，至多 −4

### 六、融入度（15）
得分项：活跃天数占比（≥50%→6 / 25-50%→4 / 更低→1）；近 30 天趋势（升3/平2/降0）；行业场景覆盖（≥4类→6 / 2-3类→3 / 1类→1）
扣分项：纯闲聊测试占比>30%：−2
口径：只算有真实任务的会话。

## 冷启动报告（human_sessions < 15）

不打分不定级（对外叫"冷启动中"，不叫低段位）。scores.json 里 `rank_mode: "placement"`，内容改为：
- `placement`: {done: N, need: 15}
- `profile`: 一段话画像（用了几次、都干了什么、什么时段）
- `starters`: 按用户已有会话内容推断其工作，给三个"最该先试的场景"，各含一句可照抄的开场 prompt
- `potential`: 按行业模块清单列出该用户最可能受益的 2-3 类能力
语气全程鼓励向，不出现任何负面评语。
